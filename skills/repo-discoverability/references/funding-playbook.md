# Funding playbook

How to put a working "support this project" surface on a repository, and why the
Russian payment reality pushes most of it through the `custom:` lane.

## What the surface is

Three artifacts, all generated from the `funding:` section of
`.discoverability/project.yml`:

| Artifact | Where a visitor sees it |
| --- | --- |
| `.github/FUNDING.yml` | the "Sponsor" button on the repository page |
| `package.json` `funding` | the "Support" link on the npm package page |
| README `## Support` | a visible ask for readers who never open the sidebar |

Set `funding.enabled: true`, list your targets, then run `rdk fix --apply`.

## The button only renders if GitHub can resolve it

GitHub shows the Sponsor button when `.github/FUNDING.yml` is present. The native
keys (`github`, `patreon`, `open_collective`, `ko_fi`, `liberapay`, ...) require
an eligible account on that platform. Every other platform goes in `custom:`,
which GitHub renders as additional button targets. `custom` accepts at most
**four** URLs, so pick the four you most want a visitor to see.

## Russian recipients

GitHub Sponsors does not pay out to recipients in Russia, and several native
platforms (Patreon, Ko-fi, Open Collective) carry the same payout restriction.
For a maintainer paid in Russia the working path is a `custom:` link to a
platform that does pay locally. Starting points, not endorsements:

| Platform | Model | Notes |
| --- | --- | --- |
| Boosty | donation + subscription | accepts Russian and foreign cards; pays to a Russian account |
| CloudTips | donation | Russian cards; tips-only |
| YooMoney | wallet | Russian cards; a wallet, not a public page |
| DonationAlerts | donation | Russian cards; stream-overlay oriented |
| GitHub Sponsors | recurring | **not available for Russian recipients** |

Example config:

```yaml
funding:
  enabled: true
  custom:
    - "https://boosty.to/<you>"
```

## When GitHub Sponsors is available

Outside the payout restriction, `github: [<user>]` is the highest-intent target:
the button lands on your Sponsors page and the recurring ask is native. Combine
it with one `custom:` fallback for one-off gifts.

## Legal caveat

Whether a given stream is a tax-free gift or taxable income depends on your
jurisdiction, the platform's model and how you frame the ask. This tool does not
and cannot decide that. Keep the wording as voluntary support, not payment for a
service.

## What rdk will not do

- It never overwrites a hand-written `FUNDING.yml` (one without the
  `# Generated by rdk` marker) or an existing `package.json` `funding` field.
- It appends a README `## Support` section only when one is absent, and never
  rewrites it afterwards.
- Funding is outside the discoverability score. The `hygiene.funding` check is
  informational and fires only when `enabled: true` and the artifact is missing
  or stale.
